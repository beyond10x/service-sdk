## Finding and source

At this SDK base48833c6d14ec37cb3b614fca05cf7dd78f63b743, crates/service-builder/src/lib.rs:87–96 calls ess_synth::synthesize then keeps plan/artifacts and drops target. A future ESS Rust refusal could therefore become metadata-only successful SDK output without a reader guard.

## Acceptance

A Rust target refusal from ESS prevents build_ess from returning a successful EssBuild and prevents downstream service/runtime/client/realization/output work. Errors preserve the target, source and reason sufficiently to act on the refusal. Valid no-refusal synthesis follows the previous path and yields unchanged generated bytes. The reader works with the current pinned ESS and is verified against a separately frozen corrected ESS candidate before that pin is adopted.

## Implementation boundary

Use the existing typed ESS TargetReport; do not replicate target feasibility, change ESS semantics or silently upgrade dependencies. Reject nonempty synthesis refusals immediately after synthesis and before projection generation or any later builder operation. Keep private test seams narrow and prove actual facade wiring with the candidate test, not just a fabricated report. Existing callers already propagate Result.

## Validation

Coordinator runs the full SDK task check before publication and exact-source ESS candidate compilation/refusal/valid-output checks separately. Do not call current-pin tests a reproduction of a Rust refusal the old producer never emits.
